# 只争朝夕 · FlowCampus 校园规划插件

第一方插件将校园日程、出发建议与出发前短任务接入思隅。它随 Aervox 构建，复用本地 SQLite、插件生命周期和现有会话；不运行独立 Next.js、FastAPI、Supabase 或第二套聊天服务。实施与证据见 [ITER-072](https://github.com/3yearsZhuang/Aervox-harness/blob/main/plan.md#iter-072)。

## 使用

通过 `./aervox dev web` 启动现有 API 与界面，在插件管理中确认“只争朝夕 · 校园规划”已启用。移动陪伴首页显示校园规划卡；标准工作台从任务中心进入，桌宠工作台也可通过校园卡片或导航入口打开同一管理界面。

1. 新增常用地点，在偏好中选择当前出发地点。
2. 在“课表与日程”中新增具体日期日程或周课程，也可先预览 CSV/ICS 再选择导入；参加后标记本次已到场，取消的事件不再生成出发计划。
3. 为起点与目的地填入实测或自行估算的路线分钟数，设置出发缓冲。没有路程时仍可查看日程、地点与任务，出发时间明确不可计算。
4. 新增短任务并填写预计分钟数与优先级。规划卡给出下一站、建议出发时刻和共同空档预算内的任务组合；可完成或删除任务。
5. 在现有对话中询问下一站或出发时间，模型可调用只读 `get_campus_plan`。结构化规划是数字依据，模型只解释，不自动修改课表。

页面每分钟前台刷新，也可手动刷新；示例时间不进入默认数据。手工路程始终标明估算来源。关闭界面不会删除数据，重新打开从宿主读取。

## 课表与导入

周课程按课程的 IANA 时区展开，每周从周一开始，可设置上课星期、间隔周数、跨日结束与明确截止日期，单个系列最长 367 天。“调整本次”“取消本次”和“本次已到达”只改变原课程日期对应的一次实例；调课移动到另一周仍保留原实例身份。停用、删除整个系列分别操作，删除系列同时删除其单次例外。当地时间跨夏令时时保持课程钟点；不存在的实例不平移到其他时刻，手工调课遇到不存在或有歧义的时刻会拒绝保存。

“导入课表”接受最多 1 MiB、512 条记录的 CSV 或 ICS。先创建地点；文件地点须匹配已有名称/标识，或由用户明确选择统一地点。解析和预览不写入数据。新增默认勾选，更新默认不选，完全重复不再写入；全部错误修正后才可确认所选记录。更新周课程会替换该系列的课表字段与单次例外，确认前逐项核对。

- CSV 表头包含 `title,place`；单次日程使用带偏移的 `start_at,end_at`，周课程使用 `start_date,until_date,start_time,end_time,weekdays`，不能在同一行混用。`weekdays` 使用 1–7，以 `;` 或 `|` 分隔；可选 `uid,timezone,interval_weeks,end_day_offset`。有 `uid` 时按来源更新同一记录，无 `uid` 时内容变化会成为新记录。
- ICS 接受静态 iCalendar 2.0 公历中的具体时间事件与有界 `WEEKLY`。支持 `BYDAY`、`INTERVAL`、`COUNT` 或 `UNTIL`、`EXDATE` 和 `RECURRENCE-ID` 单次调课；无结束规则必须明确选择导入截止日期。UTC、IANA `TZID` 和按当前时区解释的浮动时间均可使用。折叠时刻选择较早实例；不支持的规则、全天日期、自定义时区组件、附件和通知组件会拒绝导入，邀请与远程取消指令也不处理。说明性网址仅提示，不访问。

预览绑定读取时的 revision 与生命周期，数据变化后必须重新预览。课程编辑草稿也绑定原快照；重新加载不会让旧草稿自动覆盖新课程，须核对最新条目后重新进入编辑或另存为新系列。草稿在同一插件实例中切换界面时保留，停用或释放实例时丢弃；草稿和预览不作为业务真源。

## 数据与并发

校园业务保存在插件配置的版本化 `state` 文档，最多 64 个地点、128 个具体日期事件、128 个任务、128 条路程、64 个课程系列与 512 个单次例外。写入通过绑定当前插件的宿主配置 Port，复用 Schema、revision CAS 和生命周期代际，禁止插件直接访问 SQLite。界面保留编辑草稿；冲突后先重新读取并核对，再明确保存，不能盲重试覆盖另一端修改。

本次扩展保持文档 `version: 1` 与配置 `schemaVersion: 1`，新增课表数组和来源标识均为可选字段，旧 v1 文档按原样读取，不自动生成课程或改写已有数据。带扩展字段的文档需要本次 Schema 和代码完整配对；此前实现不支持这些字段，不能用于自动降级或任意嵌套文档转换，回退时保留完整导出与原数据。

停用或代码缺席撤销卡片、工具和端点，既有配置保留。插件内“导出校园数据”重新读取宿主快照并下载 JSON，不包含未提交草稿；“导出分发包”仅导出安装资源，不包含校园数据。插件管理“恢复默认”清空校园配置；显式卸载按宿主规则删除配置与 Secret。需要保留日程时先导出。停用或缺包后，可在宿主插件管理的“更多操作”导出已保存普通数据，或明确确认卸载并删除数据；导出排除 Secret、默认值与 orphaned 字段，不重新启用插件。Secret、位置观察和轨迹不进入校园文档。

未合入的旧候选使用 `flowcampus` 身份，新生态首次发布使用 `ap-tool-flowcampus`。旧候选试用记录不会被重命名、覆盖或合并到新身份，也不加入九个已发布第一方身份的迁移映射；如需保留试用内容，可先从宿主旧记录导出，继续保留原记录核对。

## 接口与构建

- `GET /v1/plugins/ap-tool-flowcampus/state`：返回校园文档、revision 与生命周期代际。
- `PUT /v1/plugins/ap-tool-flowcampus/state`：完整校园文档与预期版本一起保存。
- `GET /v1/plugins/ap-tool-flowcampus/plan`：从一次文档快照计算规划；测试可传带时区的 `at`。
- `@aervox/plugin-flowcampus/domain`：共享 Schema、类型与纯规划器。
- `@aervox/plugin-flowcampus/server`：API/工具贡献。
- `@aervox/plugin-flowcampus/ui`：受信 Vue 界面贡献。

在仓库根使用 `mise exec -- pnpm --filter @aervox/plugin-flowcampus test` 和 `./aervox ci all`。`.aervox-plugin` 分发包只携带声明与允许资源，不动态加载其中的 TypeScript/Vue 实现。

## 当前边界

本批接入现有 API Transport 的移动 Web/Android 配套界面和桌面宿主，当前候选补周课表、单次调课和 CSV/ICS 预览导入，精确配对审查与发布证据由 PR 保存。独立 Android M0 的插件配置 Port 与原生内部命令尚需接线，不能据此宣称手机脱离 API 已完成校园闭环。真实高德、GPS、系统通知、锁屏后台刷新和 3D 校园地图仍待后续交付。

规划规则参考维护者的本地 `FlowCampus` 工程（`apps/api/src/flowcampus`）：出发时刻等于活动开始减路程秒数和缓冲，任务组合共同消耗空档预算。本插件用 TypeScript/Vue 重新实现并沿用验证向量，采用本目录声明的 AGPL-3.0-or-later；不复制演示库或自动导入用户数据。
